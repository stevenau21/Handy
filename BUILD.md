> Reference for making changes, testing, building, and deploying the Handy desktop app.

## Prerequisites

- **Bun** — JavaScript runtime/package manager
- **Rust** — via rustup (stable toolchain)
- **Visual Studio 2022 Build Tools** — for MSVC linker (`vcvars64.bat`)
- **LLVM** — installed at `C:\Program Files\LLVM\` (provides `libclang.dll`)
- **CMake** — for whisper-rs-sys compilation
- **Vulkan SDK** — optional, at `C:\VulkanSDK\1.4.304.1`

Key environment paths:
```
VULKAN_SDK=C:\VulkanSDK\1.4.304.1
LIBCLANG_PATH=C:\Program Files\LLVM\bin
```

## Development Workflow

### 1. Start dev server (with hot reload)

```bash
cd /d F:\projects\Handy
bun run tauri dev
```

This:
- Runs `bun run dev` (Vite dev server on `http://localhost:1420`)
- Compiles and runs the Rust binary in debug mode
- Watches for file changes and auto-reloads frontend (HMR)
- Rust changes trigger a recompile (~1 second for incremental)

**The dev app connects to the Vite dev server.** It does NOT use embedded assets.

### 2. Making frontend-only changes (React/TypeScript)

Just edit files in `src/`. Vite HMR updates instantly.

### 3. Making backend changes (Rust)

Edit files in `src-tauri/src/`. Tauri watches for changes and recompiles.

### 4. Adding new Rust commands

1. Add the command function in `src-tauri/src/commands/clipboard.rs`
2. Annotate with `#[tauri::command]` and `#[specta::specta]`
3. Register it in `src-tauri/src/lib.rs` in the `collect_commands![]` macro
4. The TypeScript bindings in `src/bindings.ts` are auto-regenerated on build
5. Call via `commands.yourCommandName()` in frontend code

### 5. InterceptEvent schema

When adding fields to `InterceptEvent` in `src-tauri/src/managers/clipboard.rs`:
1. Update the struct fields
2. Update the `InterceptEvent` type in `src/bindings.ts` to match
3. Update the popup component to use the new field

## Building the Release Binary

### Quick Release Build (no installer, just the .exe)

```bash
call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1
cargo build --release --features tauri/custom-protocol --manifest-path F:\projects\Handy\src-tauri\Cargo.toml
```

Output: `F:\projects\Handy\src-tauri\target\release\handy.exe`

The `tauri/custom-protocol` feature is **essential** — without it, the release binary tries to connect to `localhost:1420` (dev server) instead of serving embedded assets.

### Full Release Build (with NSIS installer)

```bash
call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul 2>&1
cd /d F:\projects\Handy
bun run tauri build
```

Output:
- `src-tauri\target\release\handy.exe` — standalone binary
- `src-tauri\target\release\bundle\msi\*.msi` — Windows installer
- `src-tauri\target\release\bundle\nsis\*.exe` — NSIS installer

## Common Build Issues

### 1. "Access is denied" / "failed to remove file handy.exe"

**Cause:** The old `handy.exe` process is still running and cargo can't overwrite it.

**Fix:**
```bash
taskkill /f /im handy.exe
del /f /q F:\projects\Handy\src-tauri\target\release\handy.exe
```

### 2. "Blocking waiting for file lock on build directory"

**Cause:** Stale cargo processes or leftover `.cargo-lock` files.

**Fix:**
```bash
taskkill /f /im cargo.exe
taskkill /f /im rustc.exe
del /f /q F:\projects\Handy\src-tauri\target\.cargo-lock
del /f /q F:\projects\Handy\src-tauri\target\release\.cargo-lock
```

### 3. "Unable to find libclang"

**Cause:** `LIBCLANG_PATH` not set or incorrect.

**Fix:** Ensure LLVM is installed at `C:\Program Files\LLVM\` and verify:
```bash
dir "C:\Program Files\LLVM\bin\libclang.dll"
```
- The short path `C:\PROGRA~1\LLVM\bin` may NOT work — use the full path.

### 4. Release binary opens but shows blank/doesn't work

**Cause:** Missing `--features tauri/custom-protocol` flag.

**Fix:** Always include `--features tauri/custom-protocol` in the release build command.

### 5. `tauri.conf.json` devUrl missing

Dev builds need:
```json
"beforeDevCommand": "bun run dev",
"devUrl": "http://localhost:1420",
"beforeBuildCommand": "bun run build",
"frontendDist": "../dist"
```

## Deploying the Release Build

After the release build completes:

### Option A: Pin the new binary (recommended for testing)

1. Right-click `F:\projects\Handy\src-tauri\target\release\handy.exe`
2. Select "Pin to Start" or "Pin to taskbar"
3. Use this shortcut — it will always be the latest build

### Option B: Replace the installed app

1. Find your installed Handy location:
   - Check `C:\Program Files\Handy\`
   - Check `C:\Users\<user>\AppData\Local\Programs\Handy\`
   - Or right-click the Start menu shortcut → "Open file location"
2. Close Handy completely (right-click tray icon → Quit, or `taskkill /f /im handy.exe`)
3. Copy the new `handy.exe` from `src-tauri\target\release\` to the install folder, overwriting the old one
4. Re-launch from Start menu

## Clipboard / OCR Architecture

### Backend (Rust)

**`Managers::Clipboard::ClipboardManager`** (`src-tauri/src/managers/clipboard.rs`)
- Manages clipboard DB (SQLite at `%APPDATA%/com.pais.handy/clipboard.db`)
- Runs auto-tracker polling loop (500ms intervals)
  - Text tracking: reads system clipboard text every tick
  - OCR tracking: every 8th tick (~4s), runs `ocr_clipboard_image()` on any image in clipboard
- `InterceptEvent` emitted to frontend with `intercept_id`, `text`, and `source` ("ocr" or "clipboard")
- Pending intercepts stored in `HashMap<String, String>`
- Commands: `confirm_clipboard_intercept`, `confirm_clipboard_intercept_with_text`, `confirm_clipboard_intercept_with_note`, `discard_clipboard_intercept`

**`Ocr`** (`src-tauri/src/ocr.rs`)
- Uses Windows built-in OCR engine (Windows.Media.Ocr)
- `ocr_clipboard_image()` reads image from clipboard, extracts text

### Frontend (React/TypeScript)

**`ClipboardSavePopup`** (`src/components/clipboard/ClipboardSavePopup.tsx`)
- Listens for `intercept-event` from Rust
- Routes events by `source`:
  - `"ocr"` → fills text in textarea, focuses note input for voice entry
  - `"clipboard"` → if popup is open, fills note field; otherwise opens popup with text
- Queue support: multiple OCR screenshots queue behind current popup
- Save: calls `confirmClipboardInterceptWithText` + `setClipboardEntryNote` if note exists
- Discard: calls `discardClipboardIntercept`

**Startup** (`src/App.tsx`)
- Renders `<ClipboardSavePopup />` globally (not per-tab)
- Calls `startClipboardAutoTrack()` on app load

### Data Flow

```
Screenshot (Win+Shift+S) → clipboard gets image
                           ↓
                    Auto-tracker (500ms loop)
                    every 8th tick: ocr_clipboard_image()
                           ↓
                    OCR extracts text
                           ↓
                    intercept_ocr_text() → InterceptEvent {source:"ocr"}
                           ↓
                    ClipboardSavePopup: opens popup, text in textarea
                    
Voice dictation (Handy command) → paste text to clipboard
                           ↓
                    Auto-tracker: reads clipboard text
                           ↓
                    intercept_clipboard_text() → InterceptEvent {source:"clipboard"}
                           ↓
                    ClipboardSavePopup: fills note field (if popup open)
                    Voice intercept auto-discarded
                    
User clicks Save:
  confirmClipboardInterceptWithText(intercept_id, editedText)
  + setClipboardEntryNote(entry_id, note) if note field has content
  → Entry saved to SQLite DB
```
